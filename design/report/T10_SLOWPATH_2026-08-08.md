# T10 slow path — the ion's lateral shape: the fast path FAILS its 2 % bar

**Date:** 2026-08-08 · **Code:** `response/validation/t10_slowpath.py`,
`response/solver/zextend.py` ·
**Log:** `design/report/t10/t10_prod_ny1024.log` ·
**JSON:** `design/report/t10/t10_prod_ny1024.json`
**Kernel:** production kapton+glue `greens_comb_rho2M_dk50um_g19um.npz`
(ny = 1024), 1 ns grid to 3000 ns, d = −3..+3 of both views.

> ⚠️ An earlier run of this study (2026-08-08 19:12) was **void** — it fed the
> S1 time axis (seconds) to a nanosecond grid, which flattened the kernel's

## Verdict

**FAIL.** The worst DREAM-shaped waveform residual is **8.26 %** against a 2 %
bar. Giving the ion the surface kernel's lateral shape, frozen at z = 0, for its
whole 150 µm climb is not an adequate approximation for shallow deposits sitting
over an ESL gap.

Three qualifications, all of which matter for what to do about it:

- **Integrated charge is fine.** Per-channel charge agrees to **≤0.09 %** of the
  event (≤1.7 % within a view) and the sharing fractions to **≤0.0018 absolute**
  (worst: in-gap Y, 0.0994 → 0.0976). This is a redistribution in *time*, not in
  charge, and the 180 ns DREAM shaper is what makes it visible.
- **It is confined to a corner and dies with diffusion.** 8.26 % at the
  avalanche's own 34 µm footprint, 2.66 % by σ_T = 213 µm (z = 2 mm), 0.75 % by
  477 µm (z = 10 mm), 0.20 % at the cathode. Deposits below z ≈ 2 mm are 6.7 %
  of the drift length, and only the ~31 % of them over an ESL gap fail badly.
- **The measured observable is little affected, but the honest statement needs
  two conditions, not one.** The headline +28.5 % is c1 = 0.022 → 0.028 on a
  zero-diffusion in-gap deposit, i.e. a large shift in a negligible number. But
  c1 also moves **−4.1 %** at a perfectly ordinary size (in-gap Y,
  0.380 → 0.365) — that case is saved by *amplitude*, not by c1's size: that Y
  view carries 2.4 % of the event's peak. **On a view that actually carries the
  event, the worst c1 shift is +1.5 %**, and at full drift it is zero
  (0.475 → 0.475). Quoting a single "≤2 %" here would be wrong.

Residuals are against the **event's largest shaped amplitude across both
views** — the scale a waveform residual has to use. The within-view figure
(91 % at worst) is in the JSON but is a *sharing ratio*, not a residual: it
divides by a view that holds ~2 % of the event.

Deposits are selected by ESL *phase*, never by absolute x (audit 2026-08-07 A2).
Both paths are given the identical avalanche — birth heights from the S3
measured `alpha_z_hist` (⟨z⟩ = 13.90 µm), the same ion speed (306 ns transit at
490 V), and a delivery profile `h(t)` rebuilt from that same model rather than
read from S3 — so the residual isolates the lateral approximation and nothing
else. Averaging over birth height is by quadrature, the n → ∞ limit of the plan's
"O(100) events", with no Monte-Carlo noise to mistake for a residual.

## The mechanism

Two effects, same root: `Ψ_n(k, z) = Ψ_n(k, 0)·sinh(k(g−z))/sinh(kg)` is a
low-pass filter that tightens as the ion climbs, so the kernel **broadens**
rather than merely shrinking. A single `f_ion` cannot represent that.

**1. The prompt/ion split is per channel, not global.** The fast path applies
one `f_e = ⟨z_b⟩/g = 0.0927` to every channel. The truth is
`1 − Ψ_n(z_b)/Ψ_n(0)`, a ratio of two *differently filtered* kernels: 0.0945 on
the dominant channel, and negative on checkerboard-suppressed ones, where
lifting the source *raises* the kernel.

**2. The ion's broadening moves neighbour signal earlier.** The widened
weighting field acts during the 306 ns transit; sheet transport later lets the
fast path catch up, which is why the integrals converge while the shaped peaks
do not. The 180 ns shaper sits right on that timescale.

In-gap deposits fail hardest because charge there has no DC path to ground
(plan §3 V4: "∞ in-gap"), so the kernel carries proportionally more of the
high-k structure the z-filter attacks.

## Why the numbers are believable

- **The k = 0 self-check is an identity, at 3.2e-15 and 4.1e-15.** Delete every
  k ≠ 0 mode and the slow path must reproduce the fast path exactly, since
  `1 − z/g` is the k → 0 limit of the z factor. Getting there forced the ion
  quadrature to be the *same* rectangle rule the fast path uses rather than a
  trapezoid — which also makes the residual second-order clean, both paths then
  carrying the identical O(dt) quadrature error.
- **The z lift is verified against an independent real-space FD Laplace solve**,
  which converges onto it at **order 2 in h_x with a flat constant** — the FD
  converges *to* the spectral form, so the spectral form is the exact limit.
- **The radial-|k| reduction is certified on every run** against the direct
  reduction, at 2.9e-6–3.6e-6 of the largest channel: 30× below the smallest
  number reported.
- **No Garfield.** Plan §3 point 6 specifies `ComponentGrid::LoadWeightingField`
  over S1 Ψ time slices. Those slices never existed (`solve()` returns z = 0
  only) and are not needed. Given an exact analytic lift, that route would add
  only ComponentGrid's interpolation of a resampled grid plus the unmerged local
  region-flag patch whose applicability to the weighting-field path is
  unverified — two chances at "runs cleanly, plausible, wrong". Independence is
  kept where it matters: this file shares no code with the LUT.

## How this nearly went wrong

The first run of this study reported a comfortable pass and was completely
wrong. `to_uniform` was handed the S1 product's time axis (seconds, 0 → 1e-5)
against a nanosecond grid (0 → 3000); every sample landed past the end of the
source axis, the interpolation weight clipped to 1, and the kernel collapsed to
*prompt at sample 0, fully relaxed forever after*. `kernel_lut.py:73` converts at
exactly this boundary.

**The k = 0 self-check passed at 6e-15 throughout.** It compares two paths that
read the same kernel table, so an error in building that table is invisible to
it — and it was the check being leaned on to make the residuals credible. That
is a general limit of two-path identity tests, not a quirk of this bug. Caught
by a parallel audit session, not by this one.

`to_uniform` now raises rather than extrapolating past the product's own axis,
so the ambiguous call fails loudly instead of silently flattening the physics.

## What this does not cover

- **W1 kernels only, and that is not neutral here.** V6
  (`design/report/V6_PAD_GAPS_2026-08-08.md`, same day) shows W1 distorts the
  sub-pad structure badly — a spurious 4.5× amplitude modulation against the
  real 1.17×. The z-lift attenuates high k as `exp(−kz)`, which is *precisely*
  that structure, so **this verdict does not automatically carry over to W2**.
  Re-run T10 against the W2 kernels when the re-solve lands.
- **One point in parameter space**: ρ_s = 2 MΩ/sq, 50 µm kapton + glue, 490 V.
  The effect is a property of the gap geometry (150 µm against a ~200 µm
  kernel) rather than of the sheet, so it should be weakly ρ_s-dependent —
  unverified.
- **Ion mobility is carried at ±30 %.** Both paths use the same value, so the
  residual is insensitive to it; the absolute transit time is not.
- **The product's 48.75 µm y sampling is the resolution floor** for the Y-view
  numbers (`--y-decimate 2` exists to measure it; not run).

## Recommendation

**Build the LUT from slow-path response templates.** Plan §7 step 5 already
specifies exactly this — `R_n(x0 mod 31.2 mm, t)`, "built once by running the
slow path over a grid of source positions and caching" — and it was never done
because the slow path did not exist. It does now, and it is cheap: the
machinery here produces those templates directly. That converts T10 from a
physics approximation into a caching question, which is the tier
`test_lut_vs_solver.py` already certifies at 1e-4.

Sequence it **after** V6's W2 re-solve, so the templates are built on kernels
that are right in the first place.
