## The two physics results

### f_ion through the real woven mesh — `response/meshcell/psi_readout.py`

The suspicion was correctly aimed: `mx17_aval_calib.py` loads the woven-mesh map
through `ComponentGrid` for the **drift** field but keeps a `ComponentConstant`
ψ = 1 − z/gap for the **weighting** field, even in the meshfield branch. So
f_ion = 0.9006 was never a through-mesh number.

The solve was already in `solve_fieldmap.py`, unnoticed: its `u_A` unit problem
(anode = +V_mesh, wires = 0, drift-top = 0) *is* the readout weighting problem.
ψ = u_A / V_mesh.

```
parallel plate   f_e 0.0994   f_ion 0.9006
true psi         f_e 0.0944   f_ion 0.9056     shift +0.0050
```

Structurally it cannot be otherwise: with the ion absorbed on a grounded wire
the electron gets 1 − ψ(z) and the ion gets ψ(z), so the split depends only on
ψ at the **birth height** — 15 µm above the ESL, where the weave's harmonics
have decayed by exp(−2π·136/67) = e⁻¹²·⁸. What the mesh does change is the
overall weighting gradient (−6.329e-3/µm vs the parallel-plate −6.667e-3/µm,
i.e. ~5 % weaker), and that scales electron and ion together so it cancels from
the ratio.

Ion backflow is a real loss channel and a 0.02 % one: T6's
`funnel_ion_endpoints.json` measured 94.8 % of ions absorbed on the wires
(ψ = 0 exactly) and 5.2 % escaping, and an escaped ion crawls at ~5 nm/ns in
E_drift so it is frozen on any DREAM timescale, carrying away ψ = 0.003.

**Gated, not asserted.** Away from the weave ⟨ψ⟩ must be *exactly* linear in z
(Laplace on a periodic cell). Fit residual **5e-8** RMS, ψ(anode) = 1.000000.
Converged: lc_wire 2.0 → 1.2 moves f_ion by 0.0000 and the slope by 0.01 %.

### The i_ion template — `response/meshcell/ion_template_check.py`

Rebuilt from four inputs sharing no code with the emitter: the T6 field map,
Garfield's Ar⁺ mobility table evaluated *at the field the ions actually see*,
the ψ above, and the measured birth/absorption height distributions.

```
                      q10   q25   q50   q75   q90   q99   [ns]
reconstruction       40.6  91.5 176.4 262.5 318.7 370.7
S3 v2 measured       39.5  89.0 171.5 255.3 309.9 357.2
deviation            +2.8  +2.8  +2.8  +2.8  +2.8  +3.8   %
analytic 306 ns rect 30.6  76.5 153.1 229.6 275.5 303.1
```

One constant, the calib's own measured `t_arrival_mean_ns` = 6.66 ns (this
reconstruction starts each ion's clock at birth; the template's starts at seed
launch).

**The finding nobody was looking for:** the amp gap runs at **123.8 Td**, where
Ar⁺'s K₀ is **1.212**, not the zero-field **1.530** that `ions.py`'s analytic
model uses. The analytic 306 ns rectangle is therefore **~21 % too fast** —
between the two ion models it is the *analytic* one that is wrong, and the
measured template being slower is a feature. Worth fixing in `ions.py` if the
analytic branch is ever used for anything but contrast.

**Species:** `mx17_aval_calib.py` hardcodes `IonMobility_Ar+_Ar.txt` for every
gas. In Ar/iC₄H₁₀ 95/5 the real drifter is an isobutane/cluster ion, but Blanc's
law puts it at K₀ ≈ 1.16 against Ar⁺'s 1.21 — **4 % slower, not 2× faster**.
Flagged to the avalanche session: harmless here, materially wrong for a future
CF₄-bearing gas, and it is a per-gas property carried as a universal constant.

### The high-pass falsification

β *is* a high-pass strength knob, so T14's own β scan already measured the
exchange rate in the real chain:

```
beta 0 -> 0.75    X p5 rise 254.4 -> 250.4 ns    undershoot -1.14 % -> -9.80 %
                  = 0.46 ns of rise per point of undershoot
```

Buying the 104 ns needed costs ~226 points of undershoot; the data requires the
undershoot to move **6.4 points shallower** (−9.8 % → −3.4 %). Scanning an extra
series high-pass over τ = 100 ns … 5 µs, the best exchange rate anywhere is
~1.0 ns/point — still ~104 points against a budget of −6.4.

Any element that differentiates slow content buys rise by deepening undershoot,
and the data demands both at once. **This falsifies the class, not one
realisation of it**, because the argument is generic to high-pass filters.

### The peaking register — inference, not a read-back

All **44** archived `CosmicTb_MX17.cfg` copies under
`/media/dylan/data/x17/cosmic_bench` carry `1 0x081F 0xD023 0x0000 0x0000`
→ peaking code 2 (180 ns), across det1/det3/det4 from January to 2026-06-16.
Uniform, no exceptions. Adopted.

The caveat belongs in the record: **the T14 target run archived no `.cfg` at
all.** `det3/mx17_det3_p2_det1_overnight_6-27-26/` contains only
`run_config.json` and the subrun directory, and that config points at a DAQ-side
template *path* (`/mnt/cosmic_data/MX17/dream_config/CosmicTb_MX17.cfg`), not an
archived file. So this is 44 identical copies of that template from *other* runs,
the most recent 11 days before the target. Strong evidence; not a read-back of
the target run's own register.

## Where the contradiction now sits

Independent of the p5 estimate, at the X median: the ion term is worth **63 ns**
(333.6 with ions, 270.3 without) and the gap to data is **50 ns**. So ~**80 %**
of the ion contribution has to disappear — an *effective* slow fraction near
0.2 against a split defended at 0.9056 by two independent routes.

**Recommendation: report this, do not fit it.** With every parameter defended, a
joint (β, f_ion) fit that closes the gap would be absorbing a modelling error,
which is exactly what the handoff's own degeneracy warning said to avoid.

## A wrong turn, recorded on purpose

A single-channel toy predicted that removing slow charge at fixed total charge
raises the peak ×1.87 — which would have unified all three defects (amplitude
×0.63, rise +104 ns, undershoot 2–3×) into one cause. Checked against T14's
measured `peak_amp_med.ratio` before sending: **0.5527 with ions → 0.6319
without = ×1.14**, not ×1.87. The toy over-predicts amplitude sensitivity ~6×,
the unification does **not** hold, and "keep amplitude separate" stands.

Toy reliability, for anyone reusing it: rise *differences* track the full chain
well (uniform ~55 ns offset: 192 vs 254 with ions, 91 vs 142 without);
undershoot scale is ~4.3× high; amplitude is unusable. That is why the high-pass
falsification above is anchored on the measured β lever rather than on the toy.
